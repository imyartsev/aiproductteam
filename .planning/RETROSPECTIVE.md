# Ретроспектива проекта

## Milestone: v1.0 — MVP

**Отправлен:** 2026-05-08
**Заархивирован:** 2026-05-10
**Этапов:** 3 | **Планов:** 5

### Что было построено

- Исправлен баг с атрибутом `use_reasoner` — флаг `HEAVY_MODEL=true` заработал корректно
- Реализован парсер `# path:` маркеров — pipeline создаёт реальные файлы из markdown-вывода агентов
- Улучшены промпты Dev и QA — стабильный Python-стек, TestClient, requirements.txt
- Создан `verify.py` — 4-шаговая верификация через Docker
- Полный демо-прогон завершён: `verify.py` → PASS, 38 тестов в Docker за 0.37s

### Что работало хорошо

- Итеративный цикл «запуск → verify → фикс промпта» оказался эффективным — каждая итерация давала конкретный сигнал
- `verify.py` как единственный критерий успеха убрал субъективность («работает или нет» — чёткий ответ)
- Разделение на маленькие планы (01-01, 02-01, 03-01..03-03) давало чёткие точки прогресса

### Что было неэффективным

- REQUIREMENTS.md не обновлялся по ходу работы — статус «Pending» оставался даже у выполненных требований
- ROADMAP.md прогресс-таблица не обновлялась после завершения этапов 2 и 3
- Промпты агентов пришлось итерировать несколько раз (3.12-slim → 3.10-slim, src/ → app/, pytest PATH) — лучше закладывать такие детали в промпты с самого начала

### Паттерны, выявленные в ходе работы

- LLM-агенты генерируют код под свои предположения о структуре — нужно явно задавать структуру в промпте
- Docker-окружение менее прощающее, чем локальный запуск — проверять именно в Docker с самого начала
- `python -m pytest` надёжнее `pytest` в окружениях с нестандартным PATH

### Ключевые выводы

1. Концепция «команды агентов» технически работает — pipeline из 6 агентов достиг цели
2. Основная сложность — не архитектура, а качество промптов (детали Docker, структура файлов)
3. После завершения v1.0 концепция переосмыслена: GSD-фреймворк решает задачи планирования и исполнения полнее

### Наблюдения по стоимости

- Модель: DeepSeek (chat + reasoner)
- Подход: sequential pipeline, 6 агентов на задачу
- Примечание: каждый прогон pipeline потребляет токены всех 6 агентов — при итерации промптов это накапливается
